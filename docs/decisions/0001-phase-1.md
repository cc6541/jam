# 0001 — Phase 0 et phase 1 (2026-10-17)

## Décisions
- Premier titre **Screw Jam** ; mécanique remplaçable (un `engine-*` par mécanique).
- **Zéro serveur, zéro coût récurrent** : config distante = JSON statique, tout le reste sur l'appareil.
- Règles v1 validées (`docs/GAME-SPEC.md`) : 2 boîtes ouvertes × 3 places, toolbox 5 → 7, joker, multi-tap.
- Monétisation et engagement (`docs/MONETIZATION.md`) : near miss + revive à prix croissant, vies, série de victoires,
  coffres, récompense quotidienne, pubs récompensées et interstitielles plafonnées, IAP (sans pub, pack de démarrage,
  tirelire). Garde-fous : pas de loot box, minuteurs réels, tout niveau gagnable sans payer.
- Sensations (`docs/JUICE.md`) : chaque `GameEvent` a un retour haptique + son + visuel.
- Modèles par défaut : session sonnet/medium ; agents opus pour architect, engine, qa (voir `docs/AGENTS.md`).
- Outils tokens : rtk via le setup script de l'environnement cloud ; founder-skill en `--quick` par défaut.

## Contrats gelés (modifier = nouvelle note ici)
- `packages/engine-screw/src/types.ts` : `LevelDef`, `GameState` (avec `overflow`, `revives`, `history`),
  actions `tap | drill | extraSlot | undo | revive`, `GameEvent` (dont `cascade`, `toolboxDanger`, `revived`).
- `packages/level-tools/schema/level.schema.json` + `validateLevel` (schéma + cohérence, équilibre couleurs/jokers).
- `packages/shell/src/ports.ts` (Storage, Clock, Ads, Iap, Analytics, RemoteConfig, Feedback, Notifications),
  `remote-config.ts` (`RemoteConfig`), `namespacedStorage` (invariant d'isolation par bundleId).

## Choix techniques
- `exampleLevel()` vit dans `engine-screw` (et non `level-tools`) pour éviter une dépendance circulaire.
- ESLint : les arguments préfixés par `_` peuvent rester inutilisés.
